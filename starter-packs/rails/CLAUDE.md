# Rails Project

## Stack

Ruby on Rails. Check `Gemfile` for the actual Rails version and key dependencies. Ruby version in `.ruby-version` or `Gemfile`.

## Commands

```bash
bin/rails server              # start dev server
bin/rails console             # Rails REPL
bin/rails generate            # code generators
bin/rails db:migrate          # run pending migrations
bin/rails db:rollback         # roll back last migration
bundle exec rspec spec/       # run full test suite
bundle exec rubocop           # lint
bundle exec rubocop -A        # lint + auto-correct safe offenses
```

## Hard rules

**Commands**
- Always use `bin/rails`, never bare `rails`. The binstub ensures the correct bundled version runs.
- Always prefix gem executables with `bundle exec` (e.g., `bundle exec rspec`, `bundle exec rubocop`). Never rely on system-installed gems.

**Testing**
- Test framework is RSpec. Tests live in `spec/`. Run with `bundle exec rspec spec/`.
- Models: `spec/models/`, controllers: `spec/requests/`, system tests: `spec/system/`.
- No untested public methods on models or service objects. Write the test before marking a task done.
- Use `FactoryBot` for fixtures — never `fixtures/*.yml` for new tests.

**Database**
- Never modify `db/schema.rb` directly. It is auto-generated by `bin/rails db:migrate`.
- Every migration must have a working `down` method. `raise ActiveRecord::IrreversibleMigration` is acceptable only when a rollback is genuinely impossible; document why.
- Check `db/schema.rb` before writing a migration to understand the current state.
- Never add `db/schema.rb` changes to a migration that doesn't own them.

**Security**
- Always use strong parameters. Never call `params.permit!` — enumerate permitted fields explicitly.
- CSRF protection is on by default. Don't disable it. For API-only controllers that need to opt out, use `protect_from_forgery with: :null_session` and document why.
- No raw SQL string interpolation. Use ActiveRecord query interface or parameterized `where("col = ?", value)`.
- Credentials go in `config/credentials.yml.enc` or `.env` (gitignored). Never hardcode secrets.

**Code style**
- Follow RuboCop defaults (`bundle exec rubocop` must pass clean before committing).
- Methods longer than 10 lines are a signal to extract. Service objects for business logic that doesn't belong in a model or controller.
- Avoid callbacks (`before_save`, `after_create`) for side effects. Use service objects or event hooks instead — callbacks make code order-dependent and hard to test.

**Never**
- Call `bundle install` without checking `Gemfile.lock` first.
- Use `update_all` or `delete_all` without a scoped `where` clause.
- Ship a migration that drops a column without a deployment plan (column must be ignored in code before it's dropped).
